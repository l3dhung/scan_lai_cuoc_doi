紙をスマホで撮影し、**台形補正 → 読みやすさ調整 → 複数ページ整理 → 提出条件に合わせたPDF化 → 保存・共有**までブラウザーだけで完結する、スマホ最優先の書類スキャナーです。

単なる「写真をPDFにするアプリ」ではなく、役所・学校・保険・会社などへ提出するときに面倒な **A4化、白黒化、1MB / 2MB以下への調整**まで一つの流れで行えます。

## 🚀 デモ

### [GitHub Pagesで提出PDFスキャナーを開く](https://ttomohisa.github.io/htmlapps-document-scanner/)

GitHub Pagesから最初のHTMLを読み込んだ後、カメラ撮影、画像読み込み、四隅検出、台形補正、画像補正、ページ整理、PDF生成、容量調整は端末内で処理されます。

選択した写真や書類が、このアプリによってサーバーへアップロードされることはありません。

## 主な機能

- スマートフォンではネイティブアプリ風のカメラUI
- カメラの **ON / OFF** に対応。OFF時は実際に `MediaStream` を停止してカメラを解放
- 背面カメラ優先、カメラ切替、対応端末ではライト制御
- カメラが対応していればネイティブズーム、非対応でも中央クロップによる **最大4×デジタルズーム**
- スマホではピンチ / スワイプ / スライダーでズーム
- 書類が安定したときに撮影する自動撮影オプション
- 書類の四隅を端末内で自動検出。辺の強さ・紙内外の明暗差・直線性・四角形形状を組み合わせ、必要なら4点を直接修正。四隅補正では1〜4倍の拡大、ホイール/ピンチ、拡大後の移動に対応
- 斜めから撮影した書類の台形補正
- 「無変換 / 自動 / カラー / グレー / 白黒」の読みやすさ調整。自動は過度な白飛びやタイル状のムラを避ける控えめな補正にし、仕上がり表示では実際の台形補正後の結果を確認
- 複数ページを連続スキャン
- ページカードをドラッグして並べ替え（タッチ操作では右上のつまみで上下・行またぎも確実に移動）
- スマホではページカードを3列表示
- 追加後のページをプレビューから再編集し、読みやすさや四隅を変更可能
- スマホでは Scan / Pages / PDF をスクロール移動ではなく画面切り替えで表示
- 出力ファイル名を自由に入力可能。`.pdf` を省略した場合は自動付与
- **1MB以下 / 2MB以下 / A4 / 白黒** の提出条件プリセット
- 容量制限に合わせてJPEG品質と解像度を段階的に調整
- A4縦 / A4横へ自動配置
- PDF生成後に実容量や設定内容を提出前チェック
- ダウンロードとWeb Share APIによる共有
- 1つのHTML内で日本語 / Englishを切替
- PC / スマートフォン両対応
- CDN、外部フォント、解析、テレメトリ、サーバー側処理なし

## 「PDFスキャナー」ではなく「提出用PDFメーカー」

実際のオンライン提出では、撮影そのものより、その後で詰まることが多くあります。

例えば、

- 写真が斜めになった
- 3枚を1つのPDFにしたい
- A4で提出する必要がある
- 1MBまたは2MB以下と言われた
- 白黒PDFが必要
- スマホからそのまま共有したい

といったケースです。

提出PDFスキャナーでは、これらを別アプリで後処理するのではなく、**撮影から提出できるPDFを作るところまで**を一つの操作フローにまとめています。

## すぐに使う

### Webで使う

[デモを開く](https://ttomohisa.github.io/htmlapps-document-scanner/)だけで利用できます。インストールやアカウント登録は不要です。

起動時はカメラOFFです。必要なときに**カメラを開始**または電源ボタンからONにできます。**画像を追加**はカメラ権限なしで使えます。電源ボタンからいつでもOFFにできます。

### HTMLをダウンロードして使う

1. このリポジトリの `dist/index.html` をダウンロードします。
2. 最新のChromiumベースブラウザー、Firefox、Safariなどで開きます。
3. **カメラを開始**を押して権限を許可するか、カメラを起動せずに**画像を追加**から既存画像を読み込みます。

PC版Chromeでは `file://` でHTMLを直接開いた場合も、明示的な開始操作でカメラを起動できます。アプリ側で「ローカルファイルだから」という理由だけでカメラを無効化することはありません。

ただし、ブラウザーやOSによってローカルHTMLのカメラ権限の扱いは異なる場合があります。

### 完全オフラインで使う

1. このリポジトリをダウンロードまたはクローンします。
2. Windowsで `build-standalone.bat` をダブルクリックするか、PowerShellのビルドスクリプトを実行します。
3. 生成された `dist/index.html` を任意の場所へコピーします。
4. 以降はそのHTML単体をネットワーク接続なしで開けます。

生成済みHTMLを使うだけなら、Python、Node.js、ローカルWebサーバーは不要です。

## 使い方

1. 必要なときだけカメラをONにするか、保存済み画像を追加します。
2. 紙全体が入るようにズームを調整して撮影します。
3. 「仕上がり」で実際の補正結果を確認し、必要なら「四隅補正」に切り替え、拡大しながら丸いハンドルを紙の端へ合わせます。
4. 「無変換 / 自動 / カラー / グレー / 白黒」を選び、ページを追加します。
5. 続けて次のページを撮影します。
6. ページカードをドラッグして順番を変更します。スマートフォンでは右上のつまみを使うと、上下・行またぎも確実に移動できます。
7. 出力ファイル名を入力します。
8. **1MB / 2MB / A4 / 白黒** などの提出条件を選ぶか、個別設定を使用します。
9. PDFを生成し、実際の容量と提出前チェックを確認します。
10. PDFを保存、または対応端末では共有シートからそのまま共有します。

### カメラ操作

- **電源** — カメラを開始 / 完全停止します。
- **ライト** — 利用中のカメラとブラウザーが対応している場合だけ使えます。
- **カメラ切替** — 利用可能なビデオ入力を切り替えます。
- **ズーム** — カメラ自身のズーム機能を優先し、利用できない場合はデジタルズームへ切り替えます。
- **自動撮影** — 書類が安定したときに自動で撮影するオプションです。
- **画像を追加** — すでに端末に保存されている写真・スキャン画像を読み込みます。

カメラをOFFにすると、単にプレビューを隠すのではなく、利用中のVideo Trackを停止してカメラを解放します。

## 提出条件プリセット

| プリセット | 動作 |
| --- | --- |
| 標準 | 厳密な容量制限を付けず通常設定で生成 |
| 1MB | 必要に応じてJPEG品質・解像度を下げ、1MB以下を目標に調整 |
| 2MB | 必要に応じてJPEG品質・解像度を下げ、2MB以下を目標に調整 |
| A4 | ページをA4縦またはA4横へ配置 |
| 白黒 | 書類ページをモノクロ化して生成 |

容量制限はベストエフォートです。画像量が多い書類では画質を大きく下げる場合があるため、小さい文字を含む書類は生成後のPDFを拡大して読めることを確認してください。

## GitHub Pagesで公開する

このリポジトリには、単一HTMLをビルドしてGitHub Pagesへ公開するワークフローが含まれています。

1. リポジトリ名を `htmlapps-document-scanner` としてGitHubへプッシュします。
2. **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選択します。
3. `main` ブランチへプッシュするか、Actions画面からPages用ワークフローを手動実行します。
4. 成功後、`https://ttomohisa.github.io/htmlapps-document-scanner/` で公開されます。

`main` へのプッシュ時には、Standalone HTMLを再生成・検証してから公開します。

## 開発とビルド

```text
.
├─ src/index.template.html       # アプリ本体
├─ app.config.json               # アプリ情報
├─ dependencies.json             # 内包依存関係の定義
├─ build-standalone.bat          # Windows用ビルド入口
├─ build-standalone.ps1          # 単一HTML生成処理
├─ scripts/
│  └─ check-repository.ps1       # リポジトリ / Standalone検証
├─ dist/
│  ├─ index.html                 # 読みやすい単一HTML版
│  └─ index.self-extract.html    # gzip自己解凍版
└─ .github/workflows/
   ├─ build-standalone.yml       # Pull Request時のビルド検証
   └─ deploy-pages.yml           # GitHub Pagesへの自動公開
```

`dist/` の生成物は直接編集せず、`src/index.template.html` を変更して再ビルドします。

### ビルドと検証

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\build-standalone.ps1
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-repository.ps1
```

主な生成物:

- `dist/index.html`
- `dist/index.self-extract.html`
- ビルド / 依存関係マニフェスト
- `dist/.nojekyll`

検証処理では、未置換プレースホルダーや意図しない外部ランタイム参照が残っていないことなどを確認します。

## プライバシーと通信防止

このアプリはローカル処理を前提に設計しています。

- カメラ映像と読み込んだ画像はブラウザー内で処理
- 四隅検出・台形補正・画像補正も端末内で実行
- PDF生成も端末内で実行
- PDFの保存・共有はユーザー操作時だけ実行
- Content Security Policyに `connect-src 'none'` を設定
- 解析、テレメトリ、ログイン、クラウド保存、書類アップロードAPIなし

GitHub Pages版では最初のHTMLを取得する通信は発生しますが、スキャンした書類内容をアプリのサーバーへアップロードする処理はありません。

ネットワークを完全に切って利用する場合は、生成済みの `dist/index.html` をローカルで直接開いてください。

## ブラウザーとカメラについて

- カメラ利用にはブラウザー / OSの権限が必要です。
- PC版Chromeでは、生成HTMLを `file://` で直接開いた場合も、明示的な開始操作でカメラを起動できます。
- 他のブラウザーではローカルファイルに対するカメラ権限の扱いが異なる場合があります。
- ライト、ネイティブズーム、カメラ切替は端末・ブラウザーの対応状況に応じて有効になります。
- ネイティブズームが利用できない場合でもデジタルズームを使用できます。
- OS共有はWeb Share API対応環境のみ利用できます。

カメラが使えない環境でも、保存済み画像からPDFを作成できます。

## 制限事項

- 白い机、低コントラスト、反射、強い影、書類の端が画面外にある場合などは四隅の自動認識が外れることがあります。
- 自動認識が外れても4点を手動で修正できます。
- OCRおよび検索可能なテキストPDF生成には対応していません。
- 1MB / 2MBなどの容量目標はベストエフォートであり、厳密なバイト数保証ではありません。
- 高解像度写真やページ数が多い書類では端末メモリを多く使用します。
- 作業中ページはあえて永続保存していないため、再読み込みやタブを閉じると現在のスキャン内容は消えます。
- Webカメラやスマートフォンカメラの機能差が大きいため、利用できるライト・ズーム・カメラ切替機能は環境によって異なります。

## 画像の読み込みとPDF出力

複数画像（1回の選択につき最大100枚）を読み込むと、編集中のファイル名と何枚目かが表示されます。「この画像をスキップ」で次の画像へ進み、「読み込みを終了」、閉じるボタン、Escapeキーで残りの読み込みを終了します。追加済みのページは残ります。「画像全体」は既存の解像度上限内で画像の端まで含めます。

作成済みPDFはファイル名だけを変更してもそのまま保存・共有できます。保存・共有には変更後の正規化された名前が使われます。ページやPDF設定を変更した場合は再作成が必要です。「すべて削除」は確認後に実行され、1ページの削除と同じく5秒間「元に戻す」が表示されます。復元時は元の編集可能なページが順番どおり、新しく追加したページの前に戻ります。

保存済みページを「プレビュー」で開いて補正範囲や読みやすさを調整し、「別ページとして保存」を選ぶと、元のページをそのまま残して直後に独立した編集可能なページを追加します。「変更を保存」は従来どおり元のページを更新します。閉じるボタンやEscapeキーでは下書きを破棄します。元ページとコピーはそれぞれ編集・回転・削除・復元できます。ドラッグのキャンセルや元の位置に戻した操作では作成済みPDFを保持し、実際に順番が変わったときだけ再作成が必要です。

開発用チェックにはPowerShellとNode.jsが必要です（npm依存関係なし）。`./scripts/check-repository.ps1` でソース、通常版、自己展開版の復元内容、ルートの `document-scanner.html` に対するワークフローテストを実行します。通常のビルドはカタログ用のルートHTMLも同期します。`./build-standalone.ps1 -OutputDirectory <path>` は既定の配布物を変更せず別フォルダーへ生成し、`./scripts/verify-standalone.ps1 -OutputDirectory <path>` で検証できます。展開内容・ハッシュの一致と、ルートHTMLのずれや別フォルダー生成時の非変更も回帰テストで確認します。
